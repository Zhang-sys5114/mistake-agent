# 会话双层调度：平台层来源派生，任务层 LLM 驱动

v2 是独立桌面 App，不接入聊天通道；不向用户暴露会话概念，GUI 不提供"新任务"入口。会话调度是独立的内核级模块（Session scheduler，非服务插件）。**整个历史是一棵消息树**：根会话（无摘要节点）从首条用户消息开始；`start_new` / 空闲超时 / `session::switch` 都是**树内分叉**——在当前消息节点下挂一棵「会话子树」，以「上一会话梗概」摘要节点开头（摘要整条链，模型上下文从该节点起算，旧会话内容不进新上下文），新用户消息随后，旧分支保留为兄弟版本（GUI `< / >` 可切回）；不再新建 SessionKey、不归档、无历史副本。切换依据是会话目标（Goal）：start_new 时主模型生成 Goal 写入会话元数据，作为 continue / update_goal / start_new 的决策依据（主模型决策，ADR-0030/0032）。偏向规则：存疑即继续。暴露历史路由（session::history / session::read）供模型按需翻阅完整消息树。护栏：切换频率限制（1 小时 5 次）；决策失败时安全默认 continue。会话文件的持久化委托 storage 服务。会话是过程记录（JSONL 追加式），业务真相在错题本。备选的用户显式会话管理（列表、恢复、新建按钮）被否决：对中学生是概念负担。
