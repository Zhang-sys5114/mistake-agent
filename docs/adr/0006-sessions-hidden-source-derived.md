# 会话双层调度：平台层来源派生，任务层 LLM 驱动

v2 是独立桌面 App，不接入聊天通道；不向用户暴露会话概念，GUI 不提供"新任务"入口。会话调度是独立的内核级模块（Session scheduler，非服务插件）：平台层按来源派生 SessionKey——v2 中来源即本地 App 本身（单键即可），未来若接入聊天渠道再按渠道+对端隔离；任务层由独立守卫模型（Guard model）决策，不进入主模型上下文——主模型不持有 session 工具。守卫模型在两个时机被调用：每回合结束时一次；用户发消息开启新回合时一次。切换依据是会话目标（Goal）：start_new 时守卫模型生成 Goal 写入会话元数据，后续比较新输入与当前 Goal 是否一致。决策为三动作：continue（目标不变）、update_goal（同会话内改写/细化 Goal）、start_new（仅当新目标明显无关且不依赖当前会话上下文）。偏向规则：存疑即继续——如"录完错题后让模型讲讲这些错题"，属于同一目标的延续，应 continue 或 update_goal，不切换以免丢失上下文。切换时旧会话归档，新会话注入旧会话梗概（交接摘要），并暴露历史路由（session::history / session::read）供模型按需翻阅完整旧记录。护栏：仅空闲时可切换、限制切换频率；守卫失败时安全默认 continue。会话文件的持久化委托 storage 服务。会话是过程记录（JSONL 追加式），业务真相在错题本。备选的用户显式会话管理（列表、恢复、新建按钮）被否决：对中学生是概念负担。
