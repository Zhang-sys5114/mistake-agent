# 0034 — session::switch 控制消息不进会话树、不随历史携带

日期：2026-08-04
状态：已采纳
关联：ADR-0030 / ADR-0032

## 背景

主模型在回合内调用 `session::switch` 后，该工具调用被当作普通 `tool_call` 消息落盘；
后续切换时 `carry_history` 又把它复制进新会话上下文。模型在新上下文里反复看到
“已调用 session::switch”，于是每轮对话都再次切换，形成自我强化的循环。

## 决策

1. **切换工具调用是控制动作，不是对话内容**：`session::switch` 的 `tool_call` 消息
   一律不落会话树（`persist_turn_messages` 过滤），其直接子消息的父链重接到切换前
   最后一条真实消息；`carry_history` 同样过滤，防止旧数据/历史携带污染新上下文。
2. **切换后的回答归新会话**：`TurnOutcome` 新增 `session_key`（回合内经 session::switch
   得到的新会话键），消息落盘、活跃路径推进、回合结束决策、缓存统计都改用它，
   不再写回已归档的旧会话。
3. 切换本身仍由 `SessionSwitch` 完成（归档 + 梗概 + 历史副本），审计与
   `Interrupt::SessionSwitched` 事件不变。

## 后果

- 模型在新会话上下文里看不到自己的切换调用，不会因“上下文里躺着 session::switch”
  而反复切换（真实链路实测：强制切换后，后续回合会话数保持不变）。
- 切换后的回答与后续对话都落在新会话，旧会话只保留到交接摘要为止，消息树语义正确。
