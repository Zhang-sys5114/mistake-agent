# 用户插件通过能力声明与受限服务句柄访问内核服务

采用 OS 式信任模型：kernel 加载特权内核插件（会话存储、验算运行时）为服务，用户插件只能在注册时通过能力声明获得受限服务句柄，无法直接触碰文件系统、进程或底层资源。内核插件之间处于同一信任边界，可经类型化接口直接互相调用；用户插件之间不直接通信，也不可见完整服务接口或内核内部。与操作系统不同，调用方向以 kernel 主动调用用户插件回调为主（批改、归档、导出等由 agent 循环驱动）；能力模型不受调用方向影响，回调仍只能访问注册时捕获的服务句柄。所有敏感操作收敛在内核插件内，kernel 成为唯一的裁决与审计点。考虑过的替代方案：无限制的全局访问（否决：信任边界形同虚设）和微内核式逐工具消息路由（否决：同进程 Rust 应用不需要这种仪式感；若将来用户插件迁到独立进程或 WASM，再重新评估）。
