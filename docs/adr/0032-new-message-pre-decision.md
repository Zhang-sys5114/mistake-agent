# 0032 — 新消息先由主模型判断是否切换上下文（先判断，后回答）

日期：2026-08-04
状态：已采纳
超驰：ADR-0030 第 1 条

## 背景

ADR-0030 把切换决策全部交给主模型，但新消息到达时默认继续当前会话，切换只发生在回合中
（`session::switch` 工具）或回合结束（`LlmTurnDecider`）。用户要求回答顺序必须是：
**先判断要不要切换上下文，再按用户消息作答**——切换决策必须在回答之前完成，不能等答完再补。

## 决策

1. `SessionScheduler::on_new_message` 在空闲超时检查后、追加用户消息前，先调用主模型
   （`LlmTurnDecider`，复用 `GuardModel` 抽象）决策 continue / update_goal / start_new：
   - `start_new`：**树内分叉新会话**——在当前叶子节点下挂一棵会话子树（「上一会话梗概」
     摘要节点开头，新用户消息随后），旧分支保留为兄弟版本；摘要节点是模型上下文边界，
     回合在分叉出的新子树中回答；
   - `update_goal`：先改写当前会话目标，再继续当前会话；
   - `continue`：继续当前会话。
2. 决策失败 / 超时 / 输出解析失败 → 继续当前会话（存疑即继续，不阻塞用户消息）。
3. 切换频率护栏（1 小时 5 次）与空目标拒绝沿用；命中护栏时降级继续当前会话。
4. 回合内 `session::switch` 工具与回合结束决策保留：模型在回答过程中仍可主动分叉，
   回合末仍可更新目标 / 分叉新会话（多层兜底，单一决策者仍是主模型）。
5. `turn_decider_prompt` 扩展：`new_text` 非空 = 新消息到达（先判断是否切换）；
   `new_text` 为 null = 回合结束（判断目标是否完成）。

## 后果

- 每条用户消息多一次轻量主模型调用（reasoning=none、结构化输出），回答顺序得到保证：
  先切上下文，再作答。
- 首条消息与系统级空闲超时切换不调用模型决策（路径不变）。
- 成本可接受；失败时零风险降级为 continue（实测 2026-08-04 双回合链路通过）。
