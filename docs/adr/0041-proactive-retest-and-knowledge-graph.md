# 主动重测回合与知识图谱

决策：两个机制，均为场景 5（长效追踪）的落地形态。

**主动重测回合**：kernel 挂 tokio 定时器（30 分钟周期）扫描所有 `schedule.json` 的 `due_at`，发现到期知识点后发起**主动回合**（proactive turn）——无用户新消息，模型输入为到期清单 + 提醒指令，产出带 `proactive` 标记的 assistant 消息入当前会话树；若回合运行中，经 InterruptBus 在回合边界排队（不抢占，复用既有语义）。防骚扰：每知识点每天最多提醒 1 次（`last_reminded_at`，跨天重置）；学生拒绝则 24h 冷却。到期后的动作链全走现有工具（`practice::generate` 出题 → `practice::check` 判分 → 事件 → 调度更新），不新增重测工具。

**知识图谱**：每学科一个 `mistakes/graph/<学科>.json`（文件名 sanitize + 路径校验），节点全局 ID = `学科::知识点`，边分三层：先验层（practice 模板依赖表，人工标注，启动即有骨架）、共现层（同一判分批次知识点对，事件驱动增量）、LLM 抽取层（后续）；跨学科边存于发起学科文件，目标节点带学科前缀。图谱双用途：ECharts 力导向图可视化的数据源 + Agentic 检索索引（新增 `tracking::graph_query` 工具：输入知识点 → 返回掌握度/邻居/关联错题/近期事件，模型回答"为什么总丢分"时调用）。

明确否决：**图数据库**（Neo4j/Memgraph 等违反本地优先 + 单二进制红线；嵌入式 indradb 与 JSONL 哲学割裂；本图规模数百节点无需引擎）与**向量语义检索**（错题/知识点是结构化数据，精确过滤 + 关键词优先，本地 embedding 成本不成比例，列为后续）。

考虑过的替代方案：纯被动 checkin 扫描（被否：无提醒学生必忘）；前端横幅常驻通知（被否：改动大且本地工具无推送场景）。
